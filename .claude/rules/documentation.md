# 文档记录要求

## 四份核心文档（硬性要求，违反即严重失误）

a. **monitor.md** — 每次 sleep 结束后必须更新训练指标
b. **results.md** — 每个实验结束后更新最终结果行
c. **innovation_brainstorm.md** — 新方法/方向想法时更新
d. **decisions.md** — 每次重要决策时写入

**文档之间数据必须一致。数据来源必须是 log 文件，绝不凭记忆。**

## results.md 报告规范

必须分区展示：
1. **纯模型结果**（无后处理）
2. +NFC 结果（如适用）
3. +Re-ranking 结果（如适用）

**NFC / Re-ranking 是通用 test-time 后处理，不是我们的训练端创新。**
不允许把 NFC/RR 提升混入训练端贡献来算增益。
模型贡献 = 无后处理结果 vs baseline 无后处理结果。

## 实验完成后必须按顺序完成

1. `monitor.md` 末尾追加最终结果和结论（3-5 行）
2. `results.md` 更新实验总表（从 log 文件复制精确数字）
3. `decisions.md` 记录新决策（如有）
4. `innovation_brainstorm.md` 更新实验反馈（如有新发现）

**以上全部完成后，才能启动下一个实验。**

## 关键原则

- **没有文档的实验等于没做过**
- 跳过文档直接跑下一个 = 严重违规
- test-time 实验（NFC、re-ranking）也必须建目录、写记录
- 负面结果同样要详细记录原因，避免重复尝试
- 创新优先：不为刷 0.1% 做无意义调参
- **禁止进入"论文收尾"模式**，禁止以"多 seed 验证"/"可视化"/"效率分析"为由停止探索
- 多 seed 验证由用户在 4090 上做，不是 Claude 的工作
- **完全自主决策**：所有决策 Claude 自己做，记录在 decisions.md

## 论文意识

实验前问自己：这个结果能放进论文哪部分？答案是"不知道"就重新设计。
每个实验都应为论文某 section 提供素材（主表 / 消融 / 可视化 / 效率 / motivation 验证）。

## 评估

**永远不要用 train.py 做评估**，会覆盖训练 log。必须用 `test.py`。
