总体判断：**TTA/Online ReID 本身已经偏红海**。不要做“BN 更新 / entropy TTA / camera-bias normalization / distance objective / online UDA 防遗忘”这类主线：BNTA、TEMP、DART3、S2P/OUDA、2025 camera-bias 分析已经覆盖很多空间。TEMP 已把 ReID TTA 定义成在线无标签适应；DART3 进一步把 camera-bias + distance objective + black-box scale-shift 做掉；S2P 覆盖 online UDA；open-world/open-set ReID 也有 2024 benchmark/system 论文。  
但还有一个可追主机会：**不是“怎么更强适应”，而是“什么时候不能适应”。**

**机会 1：Open-set Contaminated TTA / Matchability-Aware ReID TTA**

触发观察：现有 ReID TTA 默认 query 的真实人会在 gallery 里，或者至少 top-k gallery 对适应有正信息。TEMP 最小化 top-k gallery 相似度熵；DART3 最小化近邻距离。问题是现实 watch-list / 工业监控里大量 probe 根本不在 gallery，open-set ReID 早就指出“gallery 不一定包含 query person”，2024 MICRO-TRACK 也强调真实工业场景常是 open-set。此时低熵、低距离可能只是“被某个错人强吸附”，TTA 会把错匹配强化。

重定义：**ReID TTA 不是无条件 target adaptation，而是 matchability-conditioned adaptation**。隐藏变量不是 camera/occlusion/geometry，而是“当前样本是否可被 gallery 合法解释”。大家以为 TTA 要把测试样本都用起来；实际应先判断哪些样本不该参与适应。

机制草案：  
`MATE-ReID`: Matchability-Aware Test-Time Adaptation。

- 对每个 query/batch 估计 `matchability`：top-k margin、reciprocal support、跨 camera 支撑数、flip/crop augmentation rank stability、query-query recurrence。
- 高 matchability：允许 TEMP/DART3 类 entropy/distance adaptation。
- 低 matchability：拒绝参与适应；可做 entropy-max / push-away / unknown buffer，避免把 impostor 当正样本。
- 输出同时包括 closed-set rank 和 open-set reject score，用 `DIR@FAR` / accepted-mAP / AUROC 评估。

廉价 kill-switch：**零训练即可首验**。

1. 用现有 exp030a/SOLIDER frozen feature。
2. 在 Market/MSMT/occluded_duke/CARGO 上构造 open-set split：随机移除 30/50/70% gallery IDs，但保留这些 IDs 的 probes 作为 absent queries。
3. 检查 TEMP entropy / DART-style top-k distance 是否在 absent probes 上产生大量“confident false attractors”。
4. 做一个零训练 gate：`matchability = margin + reciprocal + aug-stability`，看是否显著提升 `DIR@FAR=1/5%`，且不伤标准 closed-set mAP。
5. kill 条件：如果 absent probe 的低熵/低距离不明显，或 gate 不超过简单 threshold / k-reciprocal baseline，就停。

撞车核查：  
TEMP 2024 做 ReID fully TTA 和 re-id entropy；DART3 2025 做 camera-bias distance TTA；S2P WACV 2024 做 online UDA；UniEnt CVPR 2024 做通用 open-set TTA；MICRO-TRACK 2024 做工业 open-set ReID/tracking。**目前没看到“open-set/absent-gallery contamination 下的 ReID TTA 更新选择”被直接做成主问题**。风险是 open-set TTA 和 open-set ReID 两边都有人，但交叉点还不算红海。

Verdict：**值得开 cheap-kill，优先级最高。**  
信心：**7/10**。  
首验数据：**现有 Market/MSMT/occluded_duke/CARGO 足够首验**；若要投稿更稳，后期最好补 OPeRID/Facility-ReID/OWD 这类 open-world 证据，但不是首验硬需求。

**机会 2：Delayed-Gallery Online ReID / Time-Varying Matchability**

触发观察：真实在线系统里 gallery 不是固定的。一个人第一次出现时可能不在 gallery，过一段时间才被登记或从其他 camera 进入 gallery。标准 closed-set ReID 假设 gallery 固定；open-set ReID 假设 absent 就 reject；TTA 更糟，早期 absent 样本可能被错误吸到最近 gallery，后面即使真 gallery 出现也难恢复。

重定义：**matchability 是时间变量，不是样本常量**。同一个 query identity 在 `t0` 是 absent，在 `t1` 可能 become-matchable。问题从“检索当前 gallery”变成“在线延迟确认 + 可回滚适应”。

机制草案：  
`Deferred Reciprocal Memory`。

- 低 matchability 样本不立刻拒绝为最终未知，而是进入短期 unknown memory。
- 当未来 gallery/stream 出现 reciprocal bridge，再合并为可适应样本。
- 只用 confirmed bridge 更新轻量 adapter 或 camera-time affine parameters。
- 对早期错误 nearest attachment 做 rollback，避免污染后续 TTA。

廉价 kill-switch：**仍可零训练模拟**。

1. 在 Market/MSMT/CARGO 中把同一 ID 的 gallery 样本延迟加入。
2. 比较三种策略：immediate nearest、static reject threshold、deferred memory + reciprocal bridge。
3. 指标：early false attach rate、delayed recovery DIR、online mAP over time。
4. kill 条件：deferred bridge 不能明显减少 false attach，或收益被普通 threshold/k-reciprocal 覆盖。

撞车核查：  
Lifelong ReID with Backward-Compatibility 2024 已经讨论 incrementally accumulated gallery，但它是 lifelong training/compatibility，不是无标签 test-time delayed matchability。MICRO-TRACK 2024 靠 open-set tracking 系统靠近这个场景，所以审稿风险比机会 1 高。

Verdict：**备选机会，不建议先押主线；可作为机会 1 的扩展实验。**  
信心：**5/10**。  
首验数据：Market/MSMT/CARGO 可模拟；若要撑 B 类完整稿，最好需要 CARGO 时间戳或额外真实 stream/open-set 数据。
