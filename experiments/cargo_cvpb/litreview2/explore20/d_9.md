codex
截至 2026-06-25 快速撞车后，我的判断：**open-set / open-world ReID 不是红海，但“通用 OSR 模块移植”是红海**。近年 ReID 里 open-world 多指野外域泛化或系统集成，比如 OWD/IJCV 2024 是动态野外泛化数据集，MICRO-TRACK/ECCV workshop 2024 是工业系统；真正围绕“query 不在 gallery 时拒识”的现代强基线方法不多。旧线有 2014 Open-set ReID 和 2018 APN adversarial open-world ReID，但都没覆盖强 Swin/SOLIDER 下的 gallery-conditioned 风险控制。([arxiv.org](https://arxiv.org/abs/1408.0872)) ([arxiv.org](https://arxiv.org/abs/1807.10482)) ([arxiv.org](https://arxiv.org/abs/2403.15119)) ([arxiv.org](https://arxiv.org/abs/2409.03879))

**机会 1: Gallery-Conditioned Open-Set ReID**
触发观察：大家默认“拒识 = top1 相似度/ margin 设阈值”，但 open-set speaker 的 VoxWatch 已明确指出 watchlist 变大时 out-of-set 最大分数会上升，false alarm 变严重；这在 ReID 里基本没被现代系统性做过。([arxiv.org](https://arxiv.org/abs/2307.00169))

重定义：**open-set ReID 不是单图置信度问题，而是 gallery size / gallery composition 下的极值风险控制问题**。同一 query embedding，面对 50 人 gallery 和 5000 人 gallery，拒识阈值不应相同。

机制草案：冻结 SOLIDER/Swin 特征，做 `gallery-conditioned conformal/EVT rejection`。用 train IDs 做 leave-ID-out calibration，估计不同 gallery size、shot 数、camera/style 条件下的 impostor max-score tail。测试时输出：
`argmax identity + p_unknown(q, G)`，只在 p-value 低于目标 FPIR 时接受。可加 top-ID mass、top1-top2 margin、local tail density，但核心必须是 set-conditioned calibration，不是又堆 attention。

廉价 kill-switch：零训练。
用 MSMT/Market/CARGO 构造 watchlist size `{10, 50, 100, 250, 500+}`，gallery 为 enrolled IDs，query 混 genuine + same-dataset held-out impostors。比较 raw cosine、margin、k-reciprocal、cohort z-norm、gallery-conditioned conformal。指标看 `DIR@FPIR=1%/5%`、`FPIR@TPIR=80/90%`、AUROC。若 gallery-conditioned 方法不能在至少两个数据集上让 FPIR 随 gallery size 的漂移明显变小，直接杀。

撞车核查：face/speaker watchlist 已有强邻域，face 2024 Watchlist Challenge 也说明 open-set identification 仍难；通用 OSR 2024 也在做 unknown detection/classification 分离。风险是 reviewer 说“这是 OSR calibration”。规避点必须是 ReID 的 gallery-conditioned、多相机、多 shot、强 ReID backbone 实证。([arxiv.org](https://arxiv.org/abs/2409.07220)) ([arxiv.org](https://arxiv.org/abs/2406.06351))

Verdict：**GO，最值得首验。**  
信心：**7/10**。  
现有数据：**MSMT 首选，Market/CARGO 可首验，不需要新数据**；occluded_duke 只做后续 stress，不要又回遮挡主线。

**机会 2: Domain-Matched Unknown ReID**
触发观察：open-set protocol 很容易把 unknown query 从另一个 dataset/domain 拿来，模型拒识的可能只是 dataset/camera/style OOD，不是真正“身份不在 gallery”。OWD 2024 已说明 open-world ReID 的域多样性很强，但它不是 query-absent 拒识问题。([arxiv.org](https://arxiv.org/abs/2403.15119))

重定义：**大家以为 unknown = not in gallery，其实 unknown-source distribution 是隐藏变量**。真正难的是“同一部署域、同类 camera/style 下的未注册身份”，不是跨数据集陌生人。

机制草案：做 `domain-matched open-set calibration`。同一套 frozen features 下，按 query camera、gallery camera、style cluster 或 dataset domain 条件化估计非目标分数分布；拒识阈值不全局共享，而是 camera/style-conditioned conformal threshold。方法可以和机会 1 合成一篇：`domain-matched, gallery-conditioned risk control for open-set ReID`。

廉价 kill-switch：零训练三组协议：
1. same-dataset held-out IDs 作为 unknown；
2. camera/style matched held-out IDs 作为 hard unknown；
3. cross-dataset IDs 作为 easy unknown。

如果 cross-dataset AUROC 很高、same-domain/camera-matched 明显塌，并且 camera/style-conditioned calibration 能救回 `3-5 AUROC` 或显著降低 `FPIR@TPIR`，继续。若三组差异很小，或 k-reciprocal/camera baseline 已经吃干净，杀掉。

撞车核查：近年 ReID open-world 主要撞 OWD 泛化和 MICRO-TRACK 系统，不是这个 protocol/method；通用 OSR 有 unknown 分布讨论，所以单独写“协议发现”不够，必须绑定 ReID-specific calibration 和强 frozen kill-switch。([arxiv.org](https://arxiv.org/abs/2409.03879)) ([arxiv.org](https://arxiv.org/abs/2406.06351))

Verdict：**CONDITIONAL GO，最好作为机会 1 的第二章/强对照，不建议单独押全稿。**  
信心：**6/10**。  
现有数据：**可首验**，MSMT/Market 做 same-domain，CARGO/AG-ReID.v2 做 cross-domain；暂不需要新数据。
