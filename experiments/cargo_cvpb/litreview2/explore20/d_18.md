**结论先说**
步态/骨架 ReID 不是蓝海。2024-26 已经有 OpenGait/SkeletonGait 强基线、QAGait 质量路线、GaitSTR 骨架-轮廓 refinement、DAGait 对齐、PSGait parsing skeleton、TrackletGait wild tracklet、2026 wavelet 动态流。普通“换骨架模块/加注意力/加质量门控/加轮廓融合”基本红海。OpenGait 也明确指出 SMPL 分支在真实 gait 数据上优势不稳，这和团队死区一致。([arxiv.org](https://arxiv.org/abs/2405.09138))

我觉得还能廉价试两条，都是“大家以为 skeleton/gait 已经 canonical，其实还有观测协议隐藏变量”。

**机会 1：Observation-Clock / Phase-Free Gait ReID**
触发观察：现有 gait 模型默认 frame index 就是时间，但真实监控有不同 FPS、抽帧、丢帧、变速轨迹。2026 已经有人做 skeleton velocity 的 time-frequency 动态流，说明“动态”正变热，但它反而可能放大 FPS/采样率污染。([arxiv.org](https://arxiv.org/abs/2604.03002)) TrackletGait 处理 non-periodic/occluded tracklet，但重点是采样和 silhouette robustness，不是“同一个人被不同观测时钟重采样后是否仍同一”。([arxiv.org](https://arxiv.org/abs/2508.02143))

重定义：gait ReID 的隐藏变量不是 only view / clothing / occlusion，而是 observation clock。模型可能学到“同采样节奏的人更像”，而不是“同身份更像”。

机制草案：把序列从 frame-domain 改到 phase-domain。用 2D 脚踝/膝盖周期信号估计 gait phase，把 skeleton 轨迹重采样到 0-1 步态相位；训练时做 temporal warp/drop augmentation，约束 phase-normalized identity embedding 不变，同时把 tempo/FPS 作为 nuisance head 分出去。检索时加 phase-overlap / cycle-DTW comparability score，只比较相位覆盖可比的片段。

廉价 kill-switch：零训练即可。
1. 用 OpenGait/FastPoseGait 预训练模型或公开 checkpoint，在 CASIA-B/Gait3D/GREW 上构造 query-gallery 不同 clock：0.5x/2x 抽帧、随机 drop、局部变速，但不改身份。
2. 看同 ID embedding distance 是否被采样扰动推远，R1/mAP 是否显著掉。
3. 同时用纯 2D skeleton phase-DTW/phase-overlap 作为无训练代理，看错误 top-k 是否集中在低 phase-overlap 对。
4. kill 条件：R1 掉幅 <3%，或 phase-overlap 对错误无预测力 AUROC <0.6。

撞车核查：QAGait 是 silhouette quality，DAGait 是 skeleton-guided spatial alignment，GaitSTR 是 skeleton refinement，TrackletGait 是 wild non-periodic/occluded tracklet，2026 wavelet 是显式动态建模；我没查到 2024-26 直接把 FPS/observation-clock 当 gait ReID 主问题。([arxiv.org](https://arxiv.org/abs/2401.13531)) ([arxiv.org](https://arxiv.org/abs/2503.18830)) ([arxiv.org](https://arxiv.org/abs/2404.02345))

verdict：值得先做 cheap-kill。  
信心：7/10。  
现有数据：Market/MSMT/occluded_duke/RSTPReid 不够；除非 CARGO/AG-ReID.v2 有原始视频/tracklet，否则首验应上 CASIA-B/Gait3D/GREW。可用现有算力，不必先训练。

**机会 2：Pose-Extractor Domain as Hidden Variable**
触发观察：skeleton-based gait 常被说成“去外观、轻量、可泛化”，但 skeleton 不是天然真值，是 pose estimator 的产物。FastPoseGait 文档里不同数据集本身就来自不同 pose extractor/keypoint layout：CASIA-B 用 HRNet/SimCC，OUMVLP-Pose 用 AlphaPose/OpenPose，GREW/Gait3D 用 HRNet。([arxiv.org](https://arxiv.org/abs/2309.00794)) 这意味着 skeleton ReID 可能暗含“pose 提取器域”，而论文通常只把它当预处理。

重定义：大家以为输入是 canonical 2D skeleton，其实是 detector-specific measurement。身份特征、关节置信度、missing pattern、左右肢 jitter 都可能被 pose backend 编码。

机制草案：Estimator-Consensus Skeleton ReID。对同一视频用 HRNet / RTMPose / ViTPose / YOLO-pose 生成多套 2D skeleton，训练一个 canonicalizer：输入单 detector skeleton，输出 detector-invariant phase trajectory；用 detector-adversarial loss 去掉 backend style，用 multi-estimator consistency 保留身份动态。推理时只需要一个 detector，但训练时用多 detector 伪视角。

廉价 kill-switch：也可以零训练。
1. 取 CASIA-B 或 Gait3D 小子集，同一 RGB 序列跑两个 pose estimators。
2. query 用 estimator A，gallery 用 estimator B，喂给现有 SkeletonGait/GaitGraph/GaitTR 或 handcrafted skeleton descriptor。
3. 看 cross-estimator R1 是否明显低于 same-estimator；再训练一个很小的 classifier 判断 skeleton 来自哪个 estimator。
4. kill 条件：cross-estimator R1 掉幅 <5%，且 detector classifier 接近随机，说明这个隐藏变量不强。

撞车核查：GPGait/FastPoseGait 做 pose-based gait benchmark 和 cross-dataset generalization，但不是把 pose extractor 本身作为域变量；GaitSTR 处理 skeleton noisy/inconsistent，但借 silhouette refinement，不是 cross-estimator invariance。([arxiv.org](https://arxiv.org/abs/2303.05234?utm_source=openai)) ([arxiv.org](https://arxiv.org/abs/2404.02345)) 这条相对不红，但论文风险是容易被审稿人看成 robustness benchmark，必须把“measurement protocol hidden variable”讲清楚，并证明普通 coordinate normalization / smoothing 解决不了。

verdict：次优先级，但 cheap-kill 很便宜。  
信心：6/10。  
现有数据：现有 ReID 图像集不能做核心验证；需要有连续视频。首验用 CASIA-B/Gait3D 原始 RGB 更现实。Market/MSMT 只能做弱 smoke test，不足以支撑稿件。

**不建议碰**
不要做新 skeleton map、GCN/Transformer 小改、silhouette+skeleton fusion、occlusion residual、quality gate、wavelet dynamics 单模块。这些 2024-26 都已经有人覆盖或很接近；继续做大概率又变成 0.x 刷点。
