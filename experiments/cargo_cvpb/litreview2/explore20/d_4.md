结论先说：**普通 VI-ReID/SYSU-MM01/RegDB 刷 mAP 是红海，不建议进。** 2024-26 已经挤满了 modality shared/specific、frequency、prompt/text、unsupervised clustering、re-ranking、video/aerial。能试的只剩“换评测情境/部署变量”。

**机会 1：Open-Set / No-Match VI-ReID，夜间红外 watchlist 拒识**
- 触发观察：标准 VI-ReID 默认 query 一定在 gallery 里；真实夜间红外检索里，大量 IR 行人根本不在白天可见光 watchlist。现有模型和 re-ranking 必然返回一个人，可能制造高置信 false alarm。
- 重定义：大家以为核心是 `VIS-IR alignment`，其实部署里还缺一个变量：**cross-modal positive existence**。任务从“排序”改成“排序 + 可拒识”：IR query 若不在 visible gallery，必须输出 no-match。
- 机制草案：用 Swin/SOLIDER 做 VI backbone，增加 `existence/energy` 头。训练时做 episodic gallery dropout：对部分训练身份故意移除跨模态正样本，构造 no-match episode；再用 nearest impostor 做 hard negative，学习“有跨模态证据才接受”。评测报 closed-set mAP/R1 + `DIR@FAR`、AUROC、false accept rate。
- 廉价 kill-switch：零训练可做。拿开源 VI checkpoint 或先训一个最小 baseline，在 SYSU/RegDB test split 中随机隐藏 20/50/80% 身份的 gallery 正样本，把对应 query 标成 absent。看 top-1 distance/margin 是否能区分 present vs absent；如果 AUROC 已经很高、FAR 很低，杀掉。若 re-ranking 提升 closed-set 却显著放大 absent false accept，这就是强证据。
- 撞车核查：2024-26 主流仍在闭集对齐：IDKL 做 modality-specific knowledge，MIP 做 modality/instance prompt，BDLF 做 base/detail，DMIC/DMDL 做 unsupervised modality-camera debias，HHCR 做 VI re-ranking；未查到 2024-26 直接做 open-set/no-match VI-ReID。open-world ReID 是老问题，但主要是可见光 watchlist，不是 VI 场景。
- verdict：**最值得先杀**。若 kill 成立，有 B 类方法稿空间。
- 信心：**7/10**。
- 数据：现有 Market/MSMT 只能预演 open-set 指标，不能支撑 VI 主张；需要下载 `SYSU-MM01/RegDB`，最好加 `LLCM`。

**机会 2：Thermal Rendering Gauge，红外 polarity/auto-gain 鲁棒性**
- 触发观察：红外图不是“原始温度”，通常是传感器渲染后的灰度图。白热/黑热 polarity、auto-gain、gamma、histogram window 变化不改身份，但可能大幅改变 ReID 特征。
- 重定义：大家说的是 VIS-IR modality gap，其实还有一个被 benchmark 固定住的隐藏变量：**IR rendering gauge**。模型不该依赖某个红外显示调色/亮度规范。
- 机制草案：`Thermal Gauge-Invariant VI-ReID`。对 IR 侧构造 rendering orbit：原图、反相、gamma、CLAHE、camera histogram match；训练 orbit consistency，同时保持跨 ID 分离。结构上可做双 polarity 共享 stem 或早期 rank/edge-consistency loss，RGB 分支不乱动。TTA orbit pooling 只当诊断，不当主贡献。
- 廉价 kill-switch：零训练。只改 test IR 图像：`I -> 255-I`、gamma、CLAHE、直方图匹配；标签不变。测 R1/mAP drop 和 top-k 邻居 Jaccard。若 FDMNet/MFEN 等 frequency 方法已天然稳住，或 drop <2%，直接杀。若 drop 很大，说明 benchmark 隐藏了 sensor rendering shift。
- 撞车核查：有近邻但不完全撞车。FDMNet 明确做 frequency/amplitude，MFEN 做 multi-frequency lighting，Edge-Attack 利用 edge attack；但未查到 2024-26 直接把 VI-ReID 定义为 polarity/auto-gain/rendering gauge robustness。风险是审稿人会把它看成“增强/frequency 小变体”。
- verdict：**只适合作为第二条 cheap-kill**，不要先重投代码。
- 信心：**5/10**。
- 数据：需要 `SYSU-MM01/RegDB/LLCM`；现有 Market/MSMT/occluded_duke/CARGO/AG-ReID.v2/RSTPReid 不能首验 VI 结论。
