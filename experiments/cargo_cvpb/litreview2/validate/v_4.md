结论先说：原始 kill-switch “非对称包含距离 beat 对称 cosine”不够干净。它最多说明“某种 uncertainty-aware 打分有用”，不能直接证明“跨视角 ReID 本质是非对称信息包含”。要让它有证伪力，必须把“非对称”“包含方向”“图像级不确定性”分别用破坏性对照隔离出来。

还有一个方向问题要先修正：如果航拍是低清俯视、信息更欠定，它应是更宽分布；地面高清是窄分布。集合语义上更像 **地面窄分布被航拍宽分布包含**，即 `G ⊂ A`，打分应测试 `-KL(G || A)` 或“ground sample under aerial distribution”。如果写成“航拍分布 ⊆ 地面分布”，方向和叙事是反的。

**B: 加固后的 Kill-Switch 协议**
核心假设拆成三条，任何一条不成立，B 都不能作为主 re-framing：

1. 航拍确实比地面更不确定：`uncertainty(A) > uncertainty(G)`。
2. 正确方向必须有效：`G ⊂ A` 明显优于 `A ⊂ G`。
3. 收益必须来自“图像级非对称包含”，而不是归一化、难度重权重、view prior 或普通 uncertainty metric。

建议协议：

1. 固定特征
   - 冻结 Swin，只提全局均值特征 `mu`。
   - 所有 `mu` 统一 L2 norm。
   - cosine baseline 必须用同一批 `mu`，同一 eval pipeline。
   - 不要拿 MaxSim 当 B 的主要 baseline；B 应打的是最强对称全局匹配。

2. 构造方差
   - 用 TTA variance 或 token/augmentation variance 得到 `sigma`。
   - `sigma` 只能来自图像本身，不能用 ID label。
   - 方差尺度、floor、temperature 只在 validation 上调，test 一次性汇报。
   - 同时记录诊断：航拍 `trace(sigma)` 是否显著高于地面。

3. 主比较
   - `Cosine(mu_A, mu_G)`
   - `Symmetric Gaussian`: average KL / JS / Bhattacharyya
   - `Correct asymmetric`: `score = -KL(N_G || N_A)`
   - `Reverse asymmetric`: `score = -KL(N_A || N_G)`
   - `Equal-variance Mahalanobis`: 去掉图像级方差，只保留距离形式

4. 破坏性对照
   - **方向破坏**：`G ⊂ A` 必须明显好于 `A ⊂ G`。如果反向差不多，非对称故事不成立。
   - **对称化破坏**：sym-KL/JS 如果和 one-sided 一样好，说明收益来自 distribution metric，不是包含。
   - **view-median 方差**：把所有航拍方差换成航拍均值方差、所有地面换成地面均值方差。如果效果不掉，说明只是 view prior。
   - **同视角方差置换**：在同一视角内随机交换 `sigma`。如果效果不掉，说明不是图像级不确定性。
   - **hardness-matched 置换**：按 cosine 难度、feature norm、分辨率分桶后交换 `sigma`。如果效果不掉，方差只是难度代理。
   - **维度打乱**：每张图内部 shuffle `sigma` 维度。如果效果不掉，说明没有维度级“证据范围”语义。
   - **variance-only / norm-only baseline**：只用方差、feature norm、分辨率等打分或校准。如果接近主方法，说明混杂严重。
   - **合成退化正控**：对地面图做 downsample/blur/occlusion。若退化后 `sigma` 不上升，方差不能解释为信息欠定。

5. 通过标准
   B 只有在这些同时成立时才算 survive kill-switch：
   - `-KL(G || A)` 在 A→G 上优于 cosine，且优于最佳 symmetric uncertainty baseline。
   - 正确方向显著优于反向。
   - 方差置换、view-median、hardness-matched、维度打乱都会明显掉分。
   - 航拍 uncertainty 明显高于地面，且合成退化能单调提高 uncertainty。
   - true pair 的 containment distance 明显低于 impostor pair，而这个差距在破坏性对照里消失。

如果只是 `-KL(G || A)` 比 cosine 高，但 sym-KL、方差置换、view-median 也一样高，那不能说 B 成立；只能说“uncertainty/calibration 有用”。

**C: Kill-Switch 能证什么**
`avg-pool 52.37 > MaxSim 45.19` 是很好的失败观察，但还不能直接证“对齐伤判别性”。它可能只是 MaxSim 实现、token norm、top-k、temperature、token 数量、layer 选择没调好。

C 的零训练协议应改成：

- 比较 hard MaxSim、soft MaxSim、top-k MaxSim、all-token average similarity、token mean pooling、global cosine。
- 控制 token L2 norm、query/gallery token 数、layer、whitening。
- 做 same-view 正控：如果 MaxSim 在 same-view 也差，那不是极端跨视角问题，而是 MaxSim 本身不适配该 backbone。
- 做 pose/SMPL 对齐 vs random local grouping。如果 pose 对齐不比随机 grouping 好，才支持“局部可对齐性不存在”。
- 做 global+local blend。如果简单 blend 明显超过 avg，说明“对齐有害”表述过强，实际是“无约束局部匹配有害”。

C 的 kill-switch 更适合证伪“局部对齐值得追”，不适合直接证明“应学视角中性但保判别特征”。

**D: 不建议用零训练 Kill-Switch 当主证据**
因果 re-framing 的 `P(Y | do(view))` 不是一个冻结特征距离能干净证伪的东西。零训练最多做诊断：

- frozen feature 能否被线性 view classifier 轻易分开。
- 减去 view mean / remove view direction 后 retrieval 是否改善。
- 数据协议里 ID 与 view 是否真实 confounded。

这些能说明“view bias 存在或不存在”，但不能证明 backdoor 或 `do(view)` 机制。D 若作为主线，需要更强的 counterfactual 设计，不适合作为当前最快 kill-switch。

最务实顺序：先做加固版 B。它最接近“失败观察 → 隐藏变量 → 机制自然长出”。但判据必须是：正确非对称包含击败 cosine、击败对称分布距离、击败所有破坏性替换对照。否则不要把上涨解释成 re-framing 成立。
