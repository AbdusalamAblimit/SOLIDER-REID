- **核心改动**: 冻结 backbone 前 5 epochs，只训练 PSG + classifier + BN
- **Config**: `configs/occluded_duke/pose_psg_freeze.yml`
- **Output**: `./log/occluded_duke/exp010_psg_freeze`
- **模型**: PoseBackboneModel (PSG Stage 3 only, 同 exp007)
- **Freeze**: 前 5 epochs backbone 全冻结
- **对照**: exp007 (无 freeze, mAP 58.3%, R1 67.9%)

**重要观察**:

**决策**: 继续监控到 ep10 评估，看是否能追上 exp007

**状态**: 🔴异常
**进度**: Epoch 10/120 (8%)

| 指标 | exp010 ep10 | exp007 ep10 |
|------|-------------|-------------|
| mAP | **0.5%** | 36.0% |
| R1 | 0.7% | 45.3% |
| R5 | 2.5% | — |
| R10 | 3.5% | — |

| Acc | 3.1% | ~10% |

**重大发现**: 冻结 5 epoch 导致灾难性后果。mAP 仅 0.5%，比 exp007 同期差 35.5%！

**根因分析**:
1. 冻结期间，classifier/PSG 学习适应了 SOLIDER 预训练的固定特征空间
2. 解冻后，backbone 开始更新，特征空间发生巨变
3. classifier 的分类面和 PSG 的 gate pattern 完全失效
4. 相当于模型在 ep6 重新从零开始学习，但有了"错误"的 PSG 初始状态
5. 到 ep10 模型仍处于"重新学习"的极早期（id_global 6.1 ≈ random）

**预测**: 由于 warmup 到 ep20，模型仍在学习中。ep20 可能恢复到 exp007 ep10 的水平，但会永久落后 5-10 个 epoch。最终结果几乎不可能超过 exp007。

**决策**: 继续观察到 ep20，如果 mAP < 30% 则终止实验

### [02:09] 检查点 #4

**状态**: 🔴严重落后
**进度**: Epoch 20/120 (17%)

| 指标 | exp010 ep20 | exp007 ep20 | 差距 |
|------|-------------|-------------|------|
| mAP | **4.9%** | ~46% | **-41%** |
| R1 | 8.6% | ~56% | -47.4% |
| R5 | 16.6% | — | — |
| R10 | 20.6% | — | — |
| id_global | 3.72 | ~3.5 | 相近 |
| Acc | 30.3% | ~40% | 略低 |

**关键矛盾**: 训练 loss (id_global 3.72) 与 exp007 ep20 (~3.5) 接近，但验证 mAP 差距巨大（4.9% vs 46%）。说明：
1. PSG 在冻结期学到了"错误"的 gate pattern，这些 gate 在训练集上因 classifier 适应而"看似有效"
2. 但 gate 实际上在扭曲特征空间，导致 test set 上的特征完全不具判别性
3. 这是一种特殊的过拟合/特征损坏模式

**结论**: 冻结 backbone 的 warmup 策略**严重有害**。原因很清楚：
- 冻结期 PSG 学到的 gate 是基于固定特征空间的
- 解冻后特征空间变化，这些 gate 不再适用
- 模型需要同时"遗忘"错误的 gate + 重新学习正确的 gate + 重新训练 backbone
- 这比从零开始还困难

**决策**: 再观察 10 epoch，如果 ep30 mAP < 35% 则终止

## 最终结论

**exp010 (Backbone Freeze Warmup) 彻底失败。** mAP 12.5% @ep30 (提前终止)。

### 失败根因
1. **特征空间不连续**: 冻结期 PSG/classifier 适应了固定的预训练特征空间，解冻后特征空间剧变导致所有学到的东西失效
2. **比零初始化更差的初始化**: 冻结期 PSG 学到的 gate pattern 不仅无效，还可能产生负面干扰（错误的 spatial modulation）
3. **训练-测试不匹配**: 训练指标（id_global 1.78, acc 71.3%）看起来"合理"，但测试 mAP 仅 12.5%。说明 PSG 的 gate 在训练集上产生了"虚假"的判别性，不具泛化性

### 关键教训
- **PSG 必须和 backbone 同时训练**: 零初始化 + 端到端训练是正确的策略
- **不要冻结预训练 backbone 来 warmup 新模块**: 新模块需要在 backbone 适应过程中"同步"学习
- **训练 loss ≈ 但测试 mAP 差距巨大 → 特征质量问题**: 不能只看训练指标判断模型状态
